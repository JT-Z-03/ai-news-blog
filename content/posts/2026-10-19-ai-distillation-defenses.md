更新系统提示词里的日期，增删一个工具，压缩太长的聊天历史。这些动作都出现在 Anthropic 的官方文档里，被列为需要检查的集成方式。应用如果继续带着旧推理记录请求特定 Claude 模型，就可能收到 400 错误。开发者没有训练竞争模型，照样会碰到反蒸馏带来的限制。

我把十月十二日的[反蒸馏说明](https://www.anthropic.com/research/distillation-defenses)和 API 文档对照了一遍。公司承认，保护措施让部分正常用户修改了集成方式，也会误拦少量良性请求。这比“阻止了多少次攻击”更值得应用开发者细看。平台保护自己的能力，会影响客户怎样保存历史、切换模型，以及为哪些请求付钱。

## 平台想保护哪一份记录

模型蒸馏可以用较强模型的输出训练另一个模型。Anthropic 这次讨论的是未经授权、利用虚假账户大规模提取能力的活动，不能把所有蒸馏研究混作一件事。它尤其在意完整推理记录，因为这些材料能提供得到答案的过程，用于训练时比只有答案更有价值。

按公司的估算，防护上线后，自有平台上被蒸馏者提取的推理 token 降到了此前的大约十分之一至百分之一。这个数字衡量它观察到的数据提取量，不能当作所有蒸馏活动的失败率。公司也没有保证效果能够长期维持。

用户看到的解释、返回的推理摘要、供模型后续使用的推理记录，也需要分清。[当前思考功能文档](https://platform.claude.com/docs/en/build-with-claude/thinking)说明，返回摘要不等于开放原始思维链；即使隐藏可读文本，签名仍能携带加密推理，供后续轮次使用。应用保存并回传这部分内容，才会遇到它的兼容规则。

一份旧推理能否继续使用，开始取决于谁生成了它，以及生成时的上下文有没有变。这把平台的保护要求带进了日常请求。

## 改了一行日期，旧推理也可能失效

[保留推理文档](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking)列出了具体范围。Fable 5.1、Opus 5.5、Sonnet 5.5 和 Haiku 5.5 会检查旧推理之前的系统提示、工具集合和消息。按 UTC 计，二〇二六年八月三十一日零时起创建的账户默认强制执行这项检查，旧账户要显式选择才强制执行。因此，开发者用老账户跑通，并不代表客户拿新账户接入也能跑通。

这也说明，十月十二日是报告的发布日期，相关规则此前已分批实施。把它写成 Claude 本周突然禁止修改上下文，会让读者找错排查的时间点。

正常应用会更新日期、修改工具、压缩历史。官方把这些操作逐项列进了排查范围。前缀检查强制执行时，保留旧推理却改变它前面的内容，普通 Messages 请求默认报错；批量请求未指定处理方式时会丢弃失效推理。开发者也可以显式选择丢弃后继续请求，但模型需要重新推理，请求成功并不等于没有代价。

文档给了一组多轮代码任务的内部测试。每轮都丢弃推理时，最高 effort 档的输出 token 增加了百分之六十七点一。这个估计误差较大，无法套成每个应用的涨价比例。它至少解释了一个后果，丢掉不可用的历史能让请求继续，却可能增加重算和等待。

切换模型又是另一种情况。目标模型读不了旧推理时，API 会从当次输入中移除相应推理块，请求仍可能成功。客户端保存的原始历史不会因此改写，切回兼容模型后仍可能复用。部分新模型的推理还限制跨账户复用。应用如果只记录有没有报错，就很难分辨模型是在接着原来的推理做事，还是没有使用那部分推理。

这些工作主要落在自行拼装请求的开发者身上。官方说明，由 Claude Code、claude.ai、Managed Agents 或 Agent SDK 构造请求，通常无需自行处理这些变化。选现成工具还是自己管理历史，现在也要算上这部分维护成本。

## 没有输出，也可能留下账单

另一项变化发生在九月二十四日。[官方发布记录](https://platform.claude.com/docs/en/release-notes/overview)写明，生物风险、竞争模型开发和推理提取这三类请求，若在输出前被拒绝，恢复按所运行模型计费。其他类别的输出前拒绝仍不收费，不能概括成“Claude 拒绝回答一律收钱”。

[拒绝与回退文档](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)把处理方式写得更具体。要求把完整内部推理放进固定字段，可能触发推理提取拒绝；这类要求也可能藏在应用的 Skill 或工具说明里。正常的简短解释、结果依据和行动摘要仍然可以要求。

拒绝甚至可以随着 HTTP 200 返回。应用还得检查停止原因和拒绝类别，才能知道有没有得到完整结果、这次是否收费。对推理提取拒绝，官方没有推荐的默认回退模型，建议先调整提示。同一请求原样重试，很难解决问题。

我更愿意把这件事看作一项明确的接口维护责任。平台有保护能力的理由，正常客户也需要知道哪些历史能改、哪些记录会丢、失败请求怎样计费。开发者验收一次升级时，得带上自己真实的历史压缩和模型切换流程，再用客户实际接入的账户检查。一次调用返回成功，回答不了这些问题。
