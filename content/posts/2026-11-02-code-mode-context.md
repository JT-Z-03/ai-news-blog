同样处理二百条日程邀请，用上 Code Mode 后，工具调用从 205 次增加到 215 次，任务耗时与费用估计反而下降。这是 Pydantic 十月二十八日公布的内部测试中的一个案例。我把测试说明和实现文档对了一遍，觉得这组反常数字比“减少工具调用”更能说明变化。

工具调用与请求模型，是两件事。一次模型回答可以发出一批工具调用。这个日程案例里，模型请求从八次降到六次，读入的词元却从约十八万四千降到三万四千。后端仍要处理邀请，省下的是模型反复读写中间数据的工作。[案例与测试方法](https://pydantic.dev/articles/why-code-mode-is-the-future)

普通的工具调用让模型给出工具名称与参数，程序执行后再把结果送回来。处理许多记录时，返回值会留在对话里，模型继续读它们、写下一批参数。即使独立操作已经合并发送，每轮带上的内容仍可能越来越多。

Code Mode 让模型先写一小段程序。分页、筛选、循环和汇总都能在程序里完成，工具仍通过原来的接口执行，最后只把选定的结果交给模型。任务规则确定以后，程序可以重复应用规则，不必让模型为每条记录重新表达一遍动作。

Pydantic 的[实现文档](https://pydantic.dev/docs/ai/harness/code-mode/)有一个很小的例子。模型写代码并行查巴黎和东京的天气，把华氏温度换算成摄氏，最后返回两个城市的换算结果。查天气的返回值留在执行环境里，模型看到的是代码选出的结果。变量保存数据，算式完成换算，这些工作不需要靠对话记忆接力。

关键也就在这里。开发者需要决定哪些数据值得让模型看，哪些只是程序继续执行所需的中间值。若代码最后又把全部原始记录打印出来，数据仍会进入上下文。用了执行工具，并不会自动得到简洁的输入。

## 长任务省下了什么

Pydantic 这次用了八个模型、购物车等五个小型应用，共完成 5276 次评分运行。应用只提供逐项增删改查，测试集中考察重复处理记录。作者报告，长任务的费用估计下降 58%，耗时下降 51%。这些是框架开发方的内部结果，基准代码尚未公开。费用按词元和接口标价折算，不能当成真实订阅账单。[测试范围与费用说明](https://pydantic.dev/articles/why-code-mode-is-the-future)

它提供的线索比一个降幅更有用。既然模型请求只少了一部分，解释性能变化就得继续看每次请求装了什么。列表翻页、按条件处理和计算总数，可以产生大量中间值，却只需要一个很短的最终回答。让这些值留在程序里，模型承担的读写就能减少。

有些工作仍需要模型逐项阅读。若处理规则取决于文本含义，程序不能只靠几个比较符号作判断；若原始数据已经全部写进用户提示，执行程序也消不掉这次输入。Code Mode 能改变数据流向，能替代多少模型判断，取决于任务本身。

短任务还会多付一笔准备成本。模型要读执行环境的说明，再写代码。上述测试在只处理五项记录时，有三类任务的费用估计反而增加约两成到四成。批量操作能分摊这些准备工作，单次查询未必值得绕这一道。[短任务的测试结果](https://pydantic.dev/articles/why-code-mode-is-the-future)

## 程序能执行到哪里

让模型写代码，接下来就得回答它能调用什么。Pydantic 使用的 [Monty](https://pydantic.dev/articles/pydantic-monty) 是用 Rust 编写的受限 Python 解释器。默认不直接访问宿主文件和网络，外部能力需要通过显式开放的工具等接口取得。开发者可以把可执行的范围限定在业务需要之内。

执行资源也有范围。按当前文档，默认每个代码片段最多使用三十秒执行时间和 256 MiB 堆内存，等待内部工具返回的时间另算。三十秒限制不能当作整项任务会在三十秒内结束的承诺，业务接口仍需要自己的超时处理。

这份限制管的是程序能接触什么、怎样占用资源。业务工具本身若允许修改记录，代码照样可以通过它发起修改。筛选条件写错，循环会把错误应用到一批对象；执行得快，也会让错误扩散得快。批量处理前核对条件，给修改保留审计记录，仍然是开发者的工作。

文档还保留了容易被忽略的恢复细节。执行片段超时可能清空程序状态，已经完成的外部操作却不会随之撤销。重新运行前需要检查部分结果，否则同一项修改可能执行两遍。配置调用追踪后，程序内部的工具调用也各自留下记录，便于查清改过哪些对象。[执行限制、恢复与调用追踪](https://pydantic.dev/docs/ai/harness/code-mode/)

我没有在本地复跑这套框架，这里的判断限于原始测试与文档。对正在做智能体的人，更值得先查的是自己的一条调用记录。模型读回了哪些数据，哪些随后只被拿来筛选、计数或逐项套用同一规则。找到这段重复工作，再决定是否交给程序，才知道 Code Mode 能替当前任务省下什么。
